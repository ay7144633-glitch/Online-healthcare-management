04   /   DATA DESIGN
MYSQL RELATIONAL MODEL

Records stay connected to their owners.

Foreign keys keep appointments, clinical notes and feedback attached to the correct accounts.

users ACCOUNT

idPK
full_name required
email unique
password_hash PBKDF2
role, specialty, active access

appointments VISIT

idPK
patient_id FK: users
doctor_id FK: users
appointment_at datetime
status, reason workflow

doctor_availability SCHEDULE

idPK
doctor_id FK: users
available_from datetime
available_to datetime
published window slot rule
users 1 : many appointments 1 : many medical_records 1 : many feedback

medical_records CLINICAL NOTE

idPK
appointment_id FK
patient_id, doctor_id FK: users
diagnosis required
notes private

feedback REVIEW

idPK
patient_id, doctor_id FK: users
rating 1 to 5
comments optional
created_at timestamp

system_settings CONFIG

setting_keyPK
setting_value clinic options
clinic name configurable
appointment length 10-180 min

13   /   SECURITY & QUALITY
SAFE BY DESIGN

Clear boundaries for every action.

The application applies role checks, input validation, secure passwords, CSRF protection and repository-based data access.

✓

Role-based access

Every protected route verifies the signed-in account’s role.

✓

Stored securely

Passwords use salted PBKDF2 rather than plain-text storage.

✓

Validated input

Appointment, scheduling and profile data are checked before persistence.

✓

CSRF protection

State-changing requests require a valid session token.

✓

Prepared SQL

Repository queries use placeholders and domain-focused methods.

✓

Unit tested

Core password behavior is covered by JUnit tests.
